# Quick Task Plan

## Objective

Add the smallest practical repo-local Node watcher that starts the existing dev process, restarts it when watched files change, and logs both the initial watch start and every restart event.

## Tasks

### Task 1: Add the restart watcher script

- **Files:** `scripts/dev-restart-watch.mjs`
- **Action:** Create a short Node script that uses the simplest watcher approach that works well on this macOS/Node repo. Prefer built-in `node:fs`, `node:child_process`, and a small debounce before adding any dependency. The script should:
  - spawn the current dev command as a child process (`pnpm dev`)
  - watch the repo paths most likely to affect development output (`src/`, `shell/`, and small root config files such as `package.json`, `tsconfig.json`, `tsup.config.ts`)
  - restart the child process when a file change is detected
  - log a clear startup message when watching begins
  - log a clear restart message with the changed path when the dev server is being restarted
  - shut down the child process cleanly on `SIGINT`/`SIGTERM`
- **Verify:** `node scripts/dev-restart-watch.mjs`, then edit or `touch src/cli/main.ts` and confirm the terminal shows both the initial "watching" log and a restart log after the file change.
- **Done:** A single runnable Node script exists and reliably restarts the dev child process on local file changes with clear log output.

### Task 2: Wire the script into repo commands and smoke-test it

- **Files:** `package.json`, `README.md`
- **Action:** Add a dedicated npm script such as `dev:restart-watch` that runs the new watcher. Update the local-development section of `README.md` with the one command to run it and a short note that it logs when it starts watching and when it restarts the dev server.
- **Verify:** `pnpm run dev:restart-watch`
  - start command succeeds
  - watcher logs its startup message
  - editing `src/cli/main.ts` produces a restart log without manual intervention
- **Done:** The watcher is discoverable through `package.json`, documented in `README.md`, and can be exercised with one repo-native command.

## Success Criteria

- The plan stays within 2 focused tasks.
- The implementation target is a short standalone Node script, not a broad refactor.
- The resulting workflow logs when watching starts and when a restart happens.
- Any helper dependency is avoided unless built-in Node watching proves insufficient during execution.
