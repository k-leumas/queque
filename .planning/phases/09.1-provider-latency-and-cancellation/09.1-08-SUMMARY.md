## Scratch latency summarizer

- **Directory:** `/var/folders/tk/mgym91f555d45tx9fnsg33680000gn/T/qq-latency.0QCz3UCF3z` (from `mktemp -d -t qq-latency`, outside the repo; `git status --porcelain` shows nothing from it)
- **Run:** `node /var/folders/tk/mgym91f555d45tx9fnsg33680000gn/T/qq-latency.0QCz3UCF3z/summarize-latency.mjs "$QQ_DEBUG_LOG_FILE"`
- **What it checks first:** it fails loudly with exit 2 and lists each missing stage unless the log has at least one of each:
  - client `command start`, `first candidate received` and `candidates received`
  - provider `cli init`, `cli first delta`, `cli first candidate`, `cli result`, and `prewarm hit` or `prewarm miss`
  - daemon `replied candidate`

  It splits sessions on the client-scope `command start` only, because the daemon logs its own `command start`.
- **What it prints:** a Markdown table with one row per `??` session. The columns are prewarm (`hit` or `miss (reason)`), command start → first candidate received, command start → candidates received, the keypress estimate (first candidate + 380 ms), the provider `cli init` / `cli first delta` / `cli first candidate` / `cli result` ms, and whether the session was aborted. After the table it prints the warm-path median of the keypress estimate, next to the 5.3 s baseline and the ~2 s target. It prints no prompt, command or request text.
- **Verified:** on an empty file it exits 2 and lists all 9 expected stages as missing. A throwaway synthetic log, deleted afterwards and never committed, checked the table shape only. No provider was stubbed, and no latency claim is based on it.
- macOS may clear `/var/folders/.../T` after a reboot or a few idle days. If the directory is gone, recreate the script with `mktemp -d`. Its logic is described above.
