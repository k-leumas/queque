## Goal Achievement

**The headline goal still holds.** Since the last report, the only source changes are:
- `git diff --stat 478f643..HEAD -- src tests shell`: six `src/providers` files, five test files, and `src/ui/CandidateSelect.tsx`.
- The `CandidateSelect.tsx` change is comment-only (ccf9a0a, the CR-02 known-limitation note).
- The daemon, client, IPC, prewarm and UI logic is byte-identical to the previously verified state.

The latency path changed in one way: there is a synchronous `stop_reason` check on the `result` event before resolve. The verifier ran one live `claude -p` turn on the installed Claude Code 2.1.285, using the production argv (`--input-format/--output-format stream-json --verbose --include-partial-messages --effort low --safe-mode --tools '' --no-session-persistence --system-prompt …`). The `result` event carried `"stop_reason":"end_turn"`, `is_error:false`, `terminal_reason:"completed"` and a JSON candidate list. So normal answers pass the new gate and still resolve on `result`. The live UAT latency and Esc evidence (UAT 1, 2, 3) therefore carries forward. RESEARCH.md Probe 2 (line 192) records the same `end_turn` value.

**The quick task's goal is achieved.** The SDK and `claude -p` paths fail closed on every non-normal stop reason, as follows:
- `isNormalStopReason` allows only `end_turn` and `stop_sequence` (provider.ts:36-38).
- Both paths share `finalCandidateList` (claude.ts:151-173). The SDK gate is at claude.ts:309.
- The runner rejects as `truncated` when `stop_reason` is present and not normal, null included (claude-process.ts:376-395). A result with no `stop_reason` key still resolves, which keeps older Claude Code builds working.
- The adapter catches only `truncated`, around both the warm and the cold attempt, and routes it to `finalCandidateList(…, false, …)` (claude-cli.ts:147-187). Because `isStalePrewarmFailure` is unchanged, a truncated warm turn is never retried cold.
- `hardError` passes the truncation copy through before the D13 mapping (claude-default.ts:70-73).
