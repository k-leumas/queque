# Phase 09.1: Provider Latency and Cancellation Verification Report

**Phase Goal:** Cut the `??` thinking→candidates wait on the `claude -p` path from ~5.3 s (keypress → candidates, measured median) toward ~2 s to the first candidate, and make Esc actually stop the in-flight model call. Evidence and measurements: `.planning/debug/llm-response-latency-profile.md`.
**Verified:** 2026-10-12T21:04:20Z
**Status:** gaps_found

## Goal Achievement

The two headline outcomes hold. The live UAT measured a warm-path median of 2838 ms from keypress to first candidate, against the 5.3 s baseline. Esc kills the real `claude -p` child. Both are backed by code, by passing tests on real child processes and a real Unix socket, and by the user's live UAT.

One must-have fails in part. The WR-05 review fix added a Backspace regression (review CR-01). The verifier reproduced it in a real Ink render. Typed keys and a Backspace that reach CandidateSelect in the same stdin read drop the Backspace. This is the FILTER editing path that D-09 and plan 09.1-09 promise. The fix is small, but the defect is open in 09.1-REVIEW-DISPOSITION.md and no test covers it, so the phase cannot close as `passed` or `human_needed`.
