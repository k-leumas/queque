# Phase 09.1 Plan 06: Bounded, backstopped claude -p runner Summary

**The stream-json runner now caps the stdout carry at 1 MiB and stderr at 64 KiB, kills a stdout flood as `invalid-result` (D13 copy), and SIGTERMs a child still alive 2 s after its `result` (SIGKILL 1.5 s later). Five new fixture scenarios prove every failure branch against real child processes.**

## Accomplishments

- `createLineParser(onEvent, { maxCarryBytes, onOverflow })` keeps a running UTF-8 byte count of the unfinished tail. Past the cap (default `STREAM_JSON_CARRY_CAP_BYTES`) it calls `onOverflow` once, drops the tail, and ignores all later input. Plan-01 behaviour (newline split, trim, blank and non-JSON lines skipped) is unchanged.
- `runClaudeTurn` handles the cases beyond the happy path:
  - A stdout overflow SIGTERMs the child and rejects with `Command failed: claude`, `reason: 'invalid-result'`, `killed: false`, `signal: null`, `code: null`, `stdout: ''`. claude-default's `hardError` maps this to the D13 copy, never TIMEOUT_MESSAGE.
  - stderr is capped at 64 KiB. Characters are kept whole, so the kept text is never more than 64 KiB.
  - Every `result` event arms an unref'd backstop timer (`backstopMs`, default 2000). The timer calls `terminateChild(child, killGraceMs)` and is cleared on `exit`.
  - `killGraceMs` (default 1500) is used by every kill the turn makes: abort, timeout, overflow and backstop.
- Fixture: added `hang-after-result`, `exit-no-result`, `die-before-init`, `stderr-flood` and `stdout-flood`. The success turn moved into `writeSuccessTurn()` with no change in behaviour. The fixture flushes stdout and stderr before `process.exit`, because pipes are asynchronous on macOS.
- Tests: `tests/claude-stream-json.test.ts` has 10 parser tests. `tests/claude-process.test.ts` has 10 new failure-path tests plus an explicit `ⓘ` assertion on the success turn. All assertions are on stage order and failure shapes, never elapsed time.

## Decisions Made

- I arm the backstop on every `result` event, not only a successful one. See deviation 1.
- An overflow that arrives after the turn has settled is a no-op in the runner. The backstop already covers a child that keeps writing after its `result`, and an immediate kill there would defeat the credential-write grace.
- The timeout test uses `budgetMs: 1000`. See deviation 2.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical] The backstop also covers is_error and schema-invalid results**
- **Found during:** Task 2
- **Issue:** The plan arms the backstop only after a successful `result`. An `is_error` (auth) or schema-invalid `result` also settles the turn, and before this change nothing killed a child that hung after one. The daemon is long-lived, so such a child would leak until it exited on its own (threat T-09.1-21).
- **Fix:** `armBackstop()` runs once for every `result` event, before the result is validated. A healthy auth failure exits within ~50 ms (Probe 3), so the timer is cleared on `exit` and never fires.
- **Files modified:** src/providers/claude-process.ts
- **Verification:** the `auth` runner test still passes, and the full suite is green.
- **Committed in:** 8d3b81d

**2. [Rule 1 - Bug, test robustness] Timeout test budget is 1000 ms instead of 200 ms**
- **Found during:** Task 2
- **Issue:** `sigterm-slow` (plan 01) installs its SIGTERM handler only after it reads the stdin line. At the observed load average of 50 to 77, a 200 ms budget could SIGTERM the child while node is still booting. The child would then die by signal instead of exiting 143, and the `exit code 143` assertion would flake (bug-206 class).
- **Fix:** the test uses `budgetMs: 1000`. The scenario streams for 10 s, so the test still times out mid-stream. Every asserted shape is unchanged.
- **Files modified:** tests/claude-process.test.ts
- **Committed in:** e451333
