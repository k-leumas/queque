## Fixed Issues

### WR-01: Daemon decodes IPC bytes per chunk, so split UTF-8 characters in the envelope are corrupted

**Files modified:** `src/daemon/server.ts`, `tests/daemon-fetch.test.ts`
**Commit:** 0175c3e
**Applied fix:** The daemon socket now calls `socket.setEncoding('utf8')`, so a StringDecoder keeps a split character intact. The data handler takes `chunk: string`, and the 256 KB cap is measured with `Buffer.byteLength` on both sides. The old check mixed UTF-16 code units with bytes. Two tests were added:
- A request whose bytes are split inside a 3-byte character keeps its non-ASCII `queryText` and `cwd`.
- A 270 KB request (90,000 code units) is refused. Before the fix it was accepted.

### WR-02: A stale prewarmed child that hangs (instead of exiting) uses the whole 25 s budget with no cold retry

**Files modified:** `src/providers/claude-process.ts`, `src/providers/claude-cli.ts`, `src/providers/claude-prewarm.ts`, `tests/claude-process.test.ts`, `tests/claude-cli-prewarm.test.ts`, `tests/claude-prewarm.test.ts`, `tests/fixtures/fake-claude-stream.mjs`
**Commit:** 5ed66aa
**Applied fix:**
- `runClaudeTurn` takes a new `initDeadlineMs` option. If no `init` arrives in time, it emits the `init-timed-out` stage (logged as `cli init timed out`), terminates the child, and rejects with the new reason `stale-prewarm` and `killed: false`.
- `isStalePrewarmFailure` now accepts `stale-prewarm`, so the existing single cold retry runs within the remaining budget.
- Warm turns get `warmInitDeadlineMs(spawnedAt)`: 1500 ms after the write (healthy write → init is 29-52 ms), plus whatever is left of a 3000 ms boot allowance. Without that allowance, a child that is taken while it may still be booting would be killed. `takePrewarmed` now returns `spawnedAt` with a hit.
- New fixture scenario `hang-before-init`. Real-child tests cover the deadline firing and the deadline never firing after `init`.

**Status: fixed: requires human verification.** This is a timing and logic change. The 1500 ms / 3000 ms values are derived from the RESEARCH probes, not measured on a slept laptop. Also, a warm child that stalls *after* `init` (a request stuck on a connection that died during sleep) is still not detected. It ends as a timeout, as before. The docstring in `claude-cli.ts` says this.

### WR-03: Daemon shutdown retires the slot but leaves the pool enabled, so an in-flight query respawns a prewarm child

**Files modified:** `src/cli/commands/daemon.ts`, `src/providers/claude-prewarm.ts` (doc comments only), `tests/daemon-fetch.test.ts`
**Commit:** c66ce51
**Applied fix:** The new exported `shutdownDaemon(server, connections, { exit, graceMs })` does three things:
1. Calls `disablePrewarm()`, which retires the slot and turns the pool off, so an in-flight query's `finally { schedulePrewarm() }` spawns nothing.
2. Destroys every open connection. Each socket's `close` aborts its turn, so `runClaudeTurn` SIGTERMs the child while the daemon is still alive.
3. After `server.close`, stays up for `SIGKILL_GRACE_MS + 100` if any connections were in flight, so the unref'd SIGKILL backstop can still fire, then exits.

`trackConnections(server)` records sockets through `server.on('connection')`, and SIGTERM/SIGINT now call `shutdownDaemon`. Tests:
- An in-flight fetch is aborted, and its emulated refill spawns nothing (the pool snapshot is `{enabled: false, state: 'empty'}`).
- With no connections, the idle child is retired, the pool is turned off, and the daemon exits at once.

Both tests fail with the old `retirePrewarmed()` call.

### WR-05: The later-arrival keep-highlight is undone by the `[query]` reset effect

**Files modified:** `src/ui/CandidateSelect.tsx`, `tests/candidate-select.test.tsx`, `tests/candidate-select-layout.test.tsx`
**Commit:** a1eef40
**Applied fix:** This uses the review's first option. The reset logic was moved into the key handlers, not deleted:
- The `useEffect(() => setSelectedIndex(0), [query])` effect is removed.
- Typing resets the selection to 0 in the same update as the query.
- Backspace also resets it, but only when the query is non-empty. That matches the old effect, which did not fire when the query was unchanged.

So the arrival branch's own pre-filter clear keeps the index it chose (D-06), and no render is committed with a stale index. Test changes:
- The mocked test that counted effects now expects 2 and checks the reset in the handler.
- New real-hooks test: a later list that clears the lbuffer keeps the highlight on row 2. It fails on the old code with `┌> ls -la`.
- New real-hooks test: typing and Backspace still move the highlight to row 0.

Note: a highlighted row that is still in the new list always matches the unchanged query, so the "kept by key" path and the clear never coincide. In practice the bug was that the effect overwrote the positional index the arrival branch had chosen, which is what the test covers.

### WR-06: The selection index is never clamped to >= 0, so -1 or NaN survives streamed arrivals

**Files modified:** `src/ui/CandidateSelect.tsx`, `tests/candidate-select-layout.test.tsx`
**Commit:** 2776f9a
**Applied fix:**

Real-hooks `it.each` test for both arrows: on an empty filtered list while rows stream, pressing the arrow twice and then receiving a matching row leaves that row highlighted, and Enter selects it. Before the fix the frame had no highlighted row.

## Skipped Issues

### WR-08: The `/tmp` socket is unauthenticated and squattable; a fake daemon is accepted and can now stream rows (pre-existing, CR-005)

**File:** `src/daemon/bootstrap.ts:222-231`, `src/daemon/server.ts:33-35`
**Reason:** Skipped: a proper fix is out of proportion for this review-fix pass, and a partial fix was ruled out.
- **What the real fix touches.** It means moving the socket into a 0700 per-user directory that is created and owner-verified, or adding a peer-uid check, plus the planned CR-005 session token. That changes:
  - `src/shared/socket-path.ts`
  - `assertSafeSocketPath`, which today only allows `/tmp/qq-*.sock`
  - the trust decisions in `ensureDaemon` (keep/replace/unknown) and `requestDaemonFetch`
  - every test that uses `/tmp/qq-*.sock` paths
- **Why the cheapest part is not enough.** An `lstat` uid check alone is partial: no peer credential check, no token, and a TOCTOU window. It would also need a new fallback path for a foreign-owned socket that the victim can neither unlink nor bind.
- **Rollout.** Moving the path would also leave the running `/tmp/qq-501.sock` daemon orphaned on the next `??`.

This should be its own planned task (CR-005).
**Original issue:** `ensureDaemon` keeps any listener on `/tmp/qq-<uid>.sock` that answers `pong` with the three flags, and any listener that does not answer. Another local user can create that path first and then receive the full envelope (cwd, query, git and filesystem context) and stream `candidate` rows back. Commands are never executed automatically, so the impact is disclosure plus social engineering on shared machines.
