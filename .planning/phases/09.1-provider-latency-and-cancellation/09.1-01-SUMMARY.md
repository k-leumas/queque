# Phase 09.1 Plan 01: Cancellable stream-json claude -p turn Summary

**Esc during `thinking…` now aborts end to end (client socket destroy → daemon `close` → AbortSignal → SIGTERM then SIGKILL of `claude -p`), and each `claude -p` turn takes its prompt as one stream-json stdin line and resolves on the zod-validated `result` event instead of process exit.**

## Accomplishments

- New runner `runClaudeTurn` (src/providers/claude-process.ts) on top of pure stream-json helpers (src/providers/stream-json.ts): stdin prompt, settle on `result`, `is_error` gate (never `subtype`), budget timeout rejected at kill time with QueQue's own `killed/SIGTERM` flags (claude exits 143 with a null signal), abort → SIGTERM, SIGKILL after 1500 ms, `spawn-error` / `exit-without-result` / `invalid-result` branches.
- `claude -p` argv is now `-p --input-format stream-json --output-format stream-json --verbose --include-partial-messages --safe-mode --tools '' --no-session-persistence --system-prompt …`; the prompt left argv (closes T-08-02-07). No model flag, no bare mode.
- Abort wiring through every layer: `FetchOptions`/`abortError`/`isAbortError` in provider.ts; claude-default re-throws aborts unmapped; daemon per-connection AbortController aborted on socket `close`, writes nothing after it; fetch-client rejects and destroys the socket on abort and never falls back afterwards; run-foreground aborts on Esc, Enter and SIGHUP/SIGTERM and never rerenders after the result; `qq client` exits right after the result is written.
- SDK `claudeAdapter` became an envelope-only wrapper so all three adapters type-check against the new `LLMAdapter` signature.
- Per-stage provider debug lines (`cli spawned`, `cli init`, `cli first delta`, `cli result`, `cli exit`, `cli aborted`, `cli timed out`) with `ms` only.
- Real-child fixture `tests/fixtures/fake-claude-stream.mjs` (success with a split ⓘ, auth, sigterm-slow) and runner tests that assert order, not wall-clock.

## Decisions Made

- `claudeAdapter` stays an options-dropping wrapper until plan 04 (as planned). No throw-on-options stub.
- `createLineParser(onEvent)` has no options argument yet. Plan 06 adds `maxCarryBytes`/`onOverflow` as an optional second parameter, which is non-breaking. The carry-cap constant name is already fixed.
- The `spawned` stage fires only when `child.pid` is defined, so a missing binary logs no `cli spawned` line before the ENOENT error.
- The test fixture also honours `FAKE_CLAUDE_ARGV_FILE` (records the argv the child received) so the "prompt not in argv" assertion is made against the real child, not just the mock. It is additive to `FAKE_CLAUDE_STDIN_FILE`.
