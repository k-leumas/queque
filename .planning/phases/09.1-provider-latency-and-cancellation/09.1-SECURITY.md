**Open (prior audit, now closed):** T-09.1-14 — the developer chose to fix it (not accept). Fix direction: treat every SDK
stop reason other than `end_turn`/`stop_sequence` as truncated (keep `completeCandidates()` rows or
throw `TRUNCATED_RESPONSE_MESSAGE`), add a `refusal` test, and consider the same gate on the
`claude -p` `result.stop_reason`.

**Re-audit (2026-10-12):** T-09.1-14 closed by 3541ffb, cc0e989, 6c5b261. Every non-normal stop reason
(including null) fails closed on both the SDK and `claude -p` paths; 122/122 provider tests pass,
`tsc --noEmit` clean. Residual (low, non-blocking): a `claude -p` result with no `stop_reason` key
is treated as `end_turn` for older Claude Code builds, so on such a build a cut-off answer still
reaches the prose fallback. Current Claude Code always sends the key (09.1-RESEARCH.md:190-192).

**Notes:** WR-02-r2 (shutdown cancels the retired child's SIGKILL fallback) is open below the
block threshold as a residual of T-09.1-03/T-09.1-15. The uncommitted `pnpm-lock.yaml`
(`@pnpm/exe`) change and untracked `.pnpm-store/` belong to another task and are outside this
phase's commits.
