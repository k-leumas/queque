# Phase 09.1 Plan 03: Streamed candidate IPC Summary

**The daemon now writes each parsed candidate to a `stream: true` client as its own `{kind:'candidate'}` message before the final `{kind:'candidates'}` done signal. A third pong flag, `streamCandidates`, gets stale daemons replaced. The client forwards rows to `onCandidate` with utf8-safe decoding, and once a row has arrived it never re-queries in-process.**

## Accomplishments

- IPC contract (`src/contracts/ipc.ts`): `fetch-candidates` gains optional `stream: true`. The response union gains `{kind:'candidate', candidate}`, validated by `commandCandidateSchema`. The pong gains `streamCandidates`. `candidates` is unchanged and remains the done signal and the authoritative list (add-alongside, per the assumption-delta decision).
- Daemon (`src/daemon/server.ts`): an `onCandidate` is built only when `req.stream === true`. It re-validates each row (T-09.1-09), writes `candidate`, and logs `replied candidate` with `{index}`. Once the connection's AbortSignal has fired, it writes nothing and logs `candidate dropped` with `{index}`, without the command text (D-14, T-09.1-11). The pong sends all three flags. The doc table describes the new reply sequence.
- `ensureDaemon` (`src/daemon/bootstrap.ts`) requires `streamCandidates === true`, so a running pre-09.1 daemon is replaced on the next `??`.
- Client (`src/daemon/fetch-client.ts`): sends `stream: true`, calls `setEncoding('utf8')`, and forwards `candidate` rows to `options.onCandidate`. A row counts as an ack. `fetchCandidatesForUi` counts the rows it forwards and rethrows the transport error once any row has arrived (D-16, T-09.1-24). With no rows yet, it falls back in-process with the caller's original options.
- `docs/SYSTEM_DESIGN.md` IPC paragraph: the stream flag, the reply sequence, the three pong flags, abort on socket close, the dropped-row log, and the no-re-query rule.

## Decisions Made

- The row index in the daemon debug lines counts every `onCandidate` call, including dropped and invalid rows, so the index matches the provider's order.
- `fetchCandidatesForUi` always passes a counting wrapper to the daemon fetch. The fallback receives the caller's original `options` object, which the test asserts by identity.
- `client.setEncoding('utf8')` plus `String(chunk)`. Node then guarantees string chunks, with partial multi-byte sequences held back by its StringDecoder.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical] requestDaemonFetch settles when the daemon closes the connection**
- **Found during:** Task 2 (RED run)
- **Issue:** `requestDaemonFetch` handled only `error`. A daemon that hung up mid-fetch (crash, restart) emitted `end`/`close` without `error`, so the client waited the full 26 s `FETCH_TIMEOUT_MS` before failing. D-16 ("rejects instead of re-querying") and the plan's "falls back … as today" case could not happen promptly.
- **Fix:** `client.on('close', () => finish(new IpcTransportError('daemon connection closed')))`. The `settled` guard makes this a no-op after a normal `candidates`/`fetch-error`/abort finish.
- **Files modified:** `src/daemon/fetch-client.ts`
- **Verification:** both Task 2 target tests pass, and the full suite passes (606/606).
- **Committed in:** `7f89384`
