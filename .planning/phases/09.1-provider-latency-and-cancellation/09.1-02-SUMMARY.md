# Phase 09.1 Plan 02: claude -p effort and streamed candidates Summary

**`claude -p` now runs with `--effort low` (overridable by a lenient `effort` key in `~/.config/qq/config.json`, never a model flag). A string-aware JSON-array scanner hands each schema-valid candidate to `options.onCandidate` the moment its object closes. The final list is the strict parse of the result text, then the streamed rows, then the old fallback.**

## Accomplishments

- **Effort (D-01, D-02):**
  - New exports in `qq-config.ts`: `EFFORT_LEVELS`, `Effort`, `DEFAULT_EFFORT = 'low'` and `resolveEffort()`.
  - The schema trims and lowercases the value, then checks it with `z.enum`. With `.optional().catch(undefined)`, a bad value (`'bogus'`, `3`) becomes `low` without the console warning and without dropping the privacy or safety patterns.
  - `buildClaudeCliArgv` inserts `'--effort', resolveEffort()` after `--include-partial-messages`. No model flag is added.
- **Docs:** a new `effort` row in the README "Configuration reference" table says that changes take effect only after a daemon restart, and `docs/config.example.json` gains `"effort": "low"`.
- **Scanner (D-05, provider half):** `createCandidateScanner` changes no state before the first `[`, so a brace or quote in wrapper prose is never tracked. Inside the array it tracks depth, strings and escapes, and JSON-parses each object that closes at depth 2. A row is emitted only if it passes `commandCandidateSchema`. Scanning stops when the array closes or after 5 rows. It keeps only the current object's text and never applies a prose fallback.
- **Strict parse:** `parseStrictCandidateList` accepts a bare or json-fenced array of 1 to 5 candidates and returns `undefined` for anything else.
- **Adapter wiring:**
  - A scanner is created only when `onCandidate` is set. It passes rows through only while `signal` is not aborted.
  - `cli first candidate` is logged once per turn.
  - The final list falls through in this order: strict parse, then streamed rows, then `parseCandidates`.
- **Test isolation:** `tests/claude-cli-provider.test.ts` now reads an empty per-test `QQ_CONFIG_FILE`, so the developer's real config can't leak into these tests.

- Key Learning: QueQue validates `effort` itself. For an unknown `--effort` value, Claude Code only prints a warning on stderr and silently uses the account default (`xhigh`). The config key is therefore lenient: trim, lowercase, `z.enum`, `.optional().catch(undefined)`. A strict enum would make `readConfigFile` drop the whole file, privacy patterns included.
- Key Learning: effort changes in config.json need a daemon restart, because `loadQqConfig` caches per process.
