# Phase 09.1 Plan 07: Streamed candidate list in the modal Summary

**CandidateSelect now grows as rows stream in. The first row is highlighted, and later rows keep the highlight and Tab toggles (by candidateKey). A `thinking…` row sits under the rows, a typed filter applies to rows that arrive later, and Zellij gets one resize at completion. A late provider failure leaves the arrived rows selectable under a dim `list may be incomplete` note.**

## Accomplishments

- `modal-layout.ts`: `CandidateListState` (`'arriving' | 'complete' | 'partial'`), `LIST_STATUS_ROW_LINES = 1` and `INCOMPLETE_LIST_NOTE`. The estimator adds the status row for arriving and partial lists that have rows (not while loading or on error). `heldPaneLines` is unchanged.
- `CandidateSelect.tsx`: new `listState` prop, default `'complete'`. The render-phase block resets selection, toggles and a zero-match pre-filter only on the first arrival. A later arrival finds the highlighted row's key in the new visible list; if the key is gone, it clamps to the last visible row. It keeps the Tab toggles, and clears a zero-match filter only while the query is still the lbuffer. The status row is `<LoadingSpinner />` (arriving) or `<Text dimColor>` with the note (partial). The layout effect returns early while `'arriving'`, and `listState` is in the layout input and the deps. No new useState.
- `run-foreground.ts`: `buildCandidateElement(candidates, error, listState = 'complete')`, a `streamed` array, and an `onCandidate` passed with the signal to `fetchCandidatesForUi`. That callback returns at once when `resolved` (D-14). Otherwise it appends the row, logs `first candidate received` once, and rerenders `annotateCandidates([...streamed], toolInventory)` as `'arriving'`. Completion rerenders the final list as `'complete'`. In `.catch`, a non-abort failure with rows logs `llm request failed after rows` `{count}`, rerenders the rows as `'partial'` and returns. With no rows, the old error path runs unchanged.

## Decisions Made

- The status row has no margin of its own. The last row block's `marginBottom={1}` is the gap, so the row adds exactly `LIST_STATUS_ROW_LINES`. The offset is a named presentational constant (global UI rule).
- `paneHold` stays keyed by array identity, as the plan says. RESEARCH Pattern 5 suggested keying it on the list instead, but the layout effect never reports while arriving, so identity keying gives exactly one shrink-to-fit at completion (hold 0 for the new final array). After that the f9o hold applies as before.
- If the highlighted key is missing from a later array, the index clamps to the last visible row. This only happens when the final list differs from the streamed rows.
