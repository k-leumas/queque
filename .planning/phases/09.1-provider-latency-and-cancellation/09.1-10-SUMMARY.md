# Phase 09.1 Plan 10: Coalesced stdin read (CR-01) Summary

**When several keys reach CandidateSelect in one stdin read, they now act exactly as if they had been pressed one at a time. Every key handler reads a `pendingInput` snapshot (query, selectedIndex, installToggled), tagged with a per-render `renderToken`, and writes its result back through `applyInput`. As a result, `ab` plus two Backspaces in one chunk restores `FILTER: type to filter…`, and Down+Enter in one chunk inserts the second row.**

## Final shape of the key handler

`useInput` first builds `live: PendingInput`. It is `pendingInput.current` when that snapshot's `render` is this render's `renderToken`. Otherwise it is `{ render: renderToken, query, selectedIndex, installToggled }` built from the closure.

The branch order is unchanged:

| Order | Key | What it does with `live` |
|-------|-----|--------------------------|
| 1 | Escape | Cancels. |
| 2 | Backspace | Does nothing on an empty `live.query`. Otherwise drops the last character and sets the selection to 0. |
| 3 | Tab | Toggles the row's `candidateKey` in a new Set built from `live.installToggled`. |
| 4 | Enter | Inserts `displayedCommand(selected, live.installToggled)` from `filterCandidates(candidates, live.query)[live.selectedIndex]`. |
| 5 | Printable | Appends the text and sets the selection to 0. |
| 6 | Up/Down | Wraps on `live.selectedIndex`, and does nothing on an empty list (WR-06). |

`applyInput(live, next)` stores `next` as the snapshot. It then calls each of `setQuery`, `setSelectedIndex` and `setInstallToggled` with a plain value, and only when that value differs from `live`.

The component still has four useState calls, two useEffect calls and two useRef calls. The arrival block and the render still filter on the committed query.
