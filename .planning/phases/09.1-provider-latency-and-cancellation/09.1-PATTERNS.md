## Pattern Assignments

### `src/providers/claude-process.ts` (NEW, streaming child runner)

**Analog:** `src/providers/claude-exec.ts`

**Failure shape to keep** (lines 19-25) — the adapter's error mapping in `claude-default.ts` reads these fields:
```ts
interface SpawnFailure extends Error {
  code?: string | number | null;
  killed?: boolean;
  signal?: NodeJS.Signals | string | null;
  stdout?: string;
  stderr?: string;
}
```

**Settled guard** (lines 56-63):
```ts
let settled = false;
const finish = (callback: () => void): void => {
  if (settled) return;
  settled = true;
  callback();
};
```

**Spawn** (lines 65-71) — change stdio to `['pipe','pipe','pipe']`, write one stream-json user line, then `stdin.end()` immediately:
```ts
const child = spawn(file, [...args], {
  cwd: options.cwd, env: options.env, stdio,
  windowsHide: options.windowsHide ?? true, shell: options.shell ?? false,
});
```

**Timeout reject shape** (lines 121-128) — reuse for budget timeout (`killed: true, signal: 'SIGTERM', code: null`) so `isTimeoutOrKilled` still maps to TIMEOUT_MESSAGE. Set own `timedOut`/`aborted` flags; do NOT derive from exit code/signal (claude exits 143, signal null).

**Spawn error** (lines 105-112): `child.on('error', ...)` → reject raw error (keeps ENOENT mapping).

**Do not copy:** `pushChunk` at lines 83-89 (`Buffer.concat` per chunk) — use running byte counts per RESEARCH Pattern 1. Do not copy the "wait for close" resolve (lines 114-166); resolve on the `result` event and arm a 2000 ms post-result backstop, SIGTERM→SIGKILL grace 1500 ms, all timers `.unref()`.

Note: keep the literal `'--system-prompt'` out of this file (steering guard, `tests/steering.test.ts:242`). Receive opaque `argv`.

### `src/providers/stream-json.ts` (NEW, line parser + result schema)

**Analog:** `src/daemon/fetch-client.ts` lines 96-118 (same carry-buffer NDJSON loop):
```ts
client.on('data', (chunk) => {
  buf += chunk.toString();
  let nl = buf.indexOf('\n');
  while (nl !== -1) {
    const line = buf.slice(0, nl).trim();
    buf = buf.slice(nl + 1);
    nl = buf.indexOf('\n');
    if (!line) continue;
    let parsed: unknown;
    try { parsed = JSON.parse(line); } catch { ...; return; }
    handleResponse(parsed);
```
Differences: feed already-decoded strings (`child.stdout.setEncoding('utf8')`), skip (not fail on) non-JSON lines, cap the carry. Result zod schema: RESEARCH Pattern 1 (gate on `is_error`, never `subtype`).

## Shared Patterns

### Child-process tests with real Node children
**Source:** `tests/claude-exec.test.ts` lines 1-40. Use `process.execPath, ['-e', SCRIPT]` fixture scripts (e.g. one emitting recorded NDJSON, one ignoring SIGTERM, one exiting 143) and `afterEach` SIGKILL cleanup of tracked children. Parser unit tests may replay recorded NDJSON; never stub the provider in smoke/latency checks.

### Debug logging
`appendDebugLog('<scope>', '<stage>', {...})` with `void` prefix (server.ts, fetch-client.ts, run-foreground.ts). Use for per-stage provider timing; latency check must use thresholds tolerant of load (bug-206).

### Capability bump
Any IPC shape change → new pong boolean in `server.ts` + required in `bootstrap.ts:96-97` + optional literal in `ipc.ts` pong schema.

### Error mapping
Errors leaving the CLI runner keep `SpawnFailure` fields so `claude-default.ts` maps auth (AUTH_FAILURE_RE on `stdout`/`stderr`) and timeout unchanged; abort errors bypass mapping.

### Steering guard
Files containing `messages.create(`, `messages.stream(` (after adding), or `'--system-prompt'` must also contain `buildSystemPrompt(` (`tests/steering.test.ts:242`).
