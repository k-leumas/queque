# Phase 09.1 Plan 04: Streamed, abortable SDK request with effort Summary

**The API-key SDK path now runs `messages.stream` + `finalMessage()` with the connection's AbortSignal, hands candidates to `onCandidate` as they parse, and sends the configured effort as `output_config.effort`, omitting it for models that reject it.**

## Accomplishments

- D-13 on the SDK path: `{ timeout, signal }` request options. An abort raises `APIUserAbortError` from `finalMessage()`. QueQue normalises it to `abortError()`, logs `request aborted` and re-throws. `claudeDefaultAdapter` passes it through unmapped, so the daemon writes nothing.
- D-05 on the SDK path: `text` deltas feed `createCandidateScanner`. Rows reach `onCandidate` in model order while the signal is live. The final list uses the same rule as `claude -p`: strict parse, then the streamed rows, then `parseCandidates`.
- D-03: `sdkOutputConfig(model, resolveEffort())` adds `output_config: { effort }` on `claude-sonnet-5` (default `low`). It omits the key for Haiku, Sonnet 4.5, Claude 3.x and the 4.0/4.1 ids. No `thinking` key is sent (adaptive by omission), and no sampling parameters.
- `claudeAdapter` now forwards options in the fourth slot, replacing plan 01's options-dropping wrapper. The steering guard treats `messages.stream(` as a model call.
- README `effort` row and `docs/EXTENSIONS.md` adapter options (`signal`, `onCandidate`) are updated.

**cerebrum.md**
- Key Learning: the SDK path uses `client.messages.stream(params, { timeout, signal })` + `await stream.finalMessage()`.
  - `finalMessage()` rejects with `APIUserAbortError` ("Request was aborted.") on abort.
  - A raw `messages.create({ stream: true })` iterator ends silently on abort, so it is not used.
  - Register the `text` listener synchronously right after `stream()` and call `finalMessage()` at once; the catching promise also prevents an unhandled 'error'/'abort' rejection.
