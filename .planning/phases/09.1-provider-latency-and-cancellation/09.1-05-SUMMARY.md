# Phase 09.1 Plan 05: Prewarmed claude -p Process Summary

**The daemon now keeps one idle `claude -p --input-format stream-json` child keyed by sha256 of {command, cwd, argv}. Matching queries run on it and skip Claude Code's ~0.9 s boot. Any mismatch retires it and runs cold. The slot is refilled after every settle, aborts included. A stale prewarm that dies without a result gets one cold retry.**

## Accomplishments
- `ClaudeTurnOptions.child`: with this option the runner skips the spawn and the `spawned` stage, then writes the stream-json user line to the prewarmed child just as it does on a cold turn. A pre-aborted signal or a zero budget terminates the child. A child that has already exited fails at once as `exit-without-result` with `sawInit: false`, so the runner never hangs waiting for a `close` that already happened.
- `src/providers/claude-prewarm.ts` exports `prewarmKey`, `enablePrewarm`, `disablePrewarm`, `schedulePrewarm`, `takePrewarmed`, `retirePrewarmed` and `prewarmSnapshot`. The pool is off by default. It handles the `child` and `stdin` error events, and its exit and error handlers only clear the slot. Retiring a child sends stdin EOF, with an unref'd SIGKILL backstop after 1500 ms.
- `claude-cli.ts` builds the spec once per query and calls `takePrewarmed(spec)`. It logs `prewarm hit` or `prewarm miss {reason}` and adds `warm` to every `cli <stage>` line. A stale warm turn gets one cold retry, logged as `prewarm retry cold`. `schedulePrewarm(spec)` runs in `finally`, so the slot is refilled after every settle.
- `daemon.ts` calls `enablePrewarm()` right after `startDaemonServer` resolves. It never spawns at start and never enables in `--ensure`. The shutdown handler calls `retirePrewarmed()` before `server.close`.

## Prewarm key

The key is the sha256 of `JSON.stringify({ command, cwd, argv })`. D-12 asks for the cwd plus a hash of the system prompt. Hashing the full argv gives the same result, because argv carries `--system-prompt` with `buildSystemPrompt(envelope)`. The key also covers `--effort` and the fixed flags on purpose: they are fixed when the process boots, so a process started with other flags or another effort must never answer. The installed-tools list is part of the system prompt, so any inventory change (installing or removing a tool, a PATH change) is a `prompt` miss by design. Warm-path measurements therefore need the same cwd and the same installed-tools set between runs.

## Decisions Made
- **When `dead` is reported.** When an idle child dies, its exit or error handler clears the slot and sets a one-shot flag. The next `takePrewarmed` then returns `{ miss: 'dead' }` once, and later takes return `empty`. A take that finds a child no longer running in the race window also returns `dead`. This keeps the miss reason useful in the debug log (stale prewarm, laptop sleep) while following the plan's rule that the handlers clear the slot.
- **Pool exit logging.** The pool logs `prewarm exit {pid, code, signal, retired}` for idle and retired children. A child the turn took logs only through the turn's own `cli exit` line. The pool tests read these lines to check the exit code or signal without holding the child handle.
- **Cold retry budget.** The retry gets whatever is left of the original budget (deadline minus now), never a fresh 25 s.
- **One scanner per attempt.** A warm attempt that failed with partial text never feeds the cold retry's scanner. A retry only happens when no row has streamed, so no row is ever sent twice.
- **Mismatch order.** When the cwd differs, the miss is reported as `cwd` even if the argv also differs. A `prompt` miss means the cwd matched but the argv or command did not.

**cerebrum.md (Key Learnings / Decision Log)**
- The prewarm pool is daemon-only: `enablePrewarm()` is called in `daemonCommand` after `startDaemonServer`, never at module top level and never in `--ensure`. main.ts imports daemon.ts for every subcommand, so a top-level call would leave idle `claude` children behind from the client's in-process fallback.
- The prewarm key is sha256 of `{command, cwd, argv}`. That equals D-12's cwd + system-prompt hash and also covers `--effort` and the fixed flags. An installed-tools change is a `prompt` miss by design.
- The slot is refilled with `schedulePrewarm(spec)` after every settle (success, error or abort), never at daemon start and never at take time. Exit and error handlers only clear the slot and never respawn.
- One cold retry happens only for a warm `exit-without-result` with no streamed rows, the signal not aborted and budget left. `is-error`, timeout and abort are never retried.
- In a worktree, `pnpm lint` processes no files (biome ignores `**/.claude`). Lint changed files by explicit path.
