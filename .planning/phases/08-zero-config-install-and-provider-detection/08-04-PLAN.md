OpenAI REST (Context7 /websites/developers_openai_api_reference and /websites/developers_openai_api, 2026-10-07):
- POST https://api.openai.com/v1/chat/completions with `Authorization: Bearer $OPENAI_API_KEY`, JSON body `{ model, messages }`.
- `developer` (or `system`) role instructions take precedence over `user`. `max_tokens` is deprecated and incompatible with o-series models; reasoning models reject non-default sampling params — send neither.
- Success body: `choices[0].message.content` (string or null) plus optional `message.refusal`.
- Error body: `{ error: { message, type, code } }`; a 401 message can include a masked key fragment, so it must not be echoed.
- The official TypeScript reference example uses model `gpt-5.5`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| env / .env.local → daemon | OPENAI_API_KEY is read from the daemon's environment or a found-up .env.local |
| daemon → api.openai.com | key in the Authorization header plus the filtered prompt cross the network |
| OpenAI response → FIFO / debug log | upstream status and error codes flow into user-visible copy and the debug log |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-13 | Information Disclosure | openai.ts errors and debug log | high | mitigate | Static copy only; never echo upstream error.message (401 text carries a masked key); debug lines carry model/status/durationMs; tests serialize log calls and assert no key, "Bearer", or prompt text. |
| T-08-14 | Information Disclosure | request destination | high | mitigate | Endpoint is the `OPENAI_CHAT_COMPLETIONS_URL` constant; provider.json has no openai baseUrl (strict schema from 08-03), so a pin cannot redirect the key. |
| T-08-15 | Information Disclosure | prompt content | medium | mitigate | Prompt built only by buildPrompt → filterContextEnvelope; test asserts a `.env` changed file never appears in the request body. |
| T-08-16 | Denial of Service | slow or hung API call | medium | mitigate | AbortSignal.timeout(25_000) under the 26s IPC and 30s FIFO budgets; timeout copy suggests retry. |
| T-08-17 | Elevation of Privilege | vendor fallthrough on OpenAI failure | high | mitigate | openai.ts imports no other adapter; tests assert Anthropic SDK, execFileAsync, and localhost:11434 are never touched on failure (D-01, D-12). |
| T-08-SC | Tampering | npm/pip/cargo installs | low | accept | No package installs; Node built-in fetch only (the `openai` npm SDK is deliberately not added). |

ASVS L1 (block on high): T-08-13, T-08-14, T-08-17 are mitigated with automated tests.
</threat_model>
