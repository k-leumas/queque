<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ZSH widget → zellij CLI | Widget passes fifo_path and req_file paths as shell arguments to zellij run |
| zellij pane → FIFO | Client process writes JSON to fifo_path; ZSH widget reads it |
| LBUFFER/RBUFFER mutation | jq-parsed result values written directly to ZLE buffer variables |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3.2-01 | Information Disclosure | FIFO world-readable in /tmp | mitigate | mktemp -u /tmp/qq-fifo.XXXXXX generates a unique path; /tmp uses sticky bit on macOS so other users cannot read; FIFO is cleaned up immediately after reading; residual window is the duration of a single interaction (~2-10s) |
| T-3.2-02 | Tampering | FIFO path injection via LBUFFER content reaching --result-file | mitigate | fifo_path is generated by mktemp -u inside the widget, not derived from LBUFFER; passed as quoted variable "$fifo_path" in the zellij run command; jq -Rs . escaping in the JSON build block prevents injection from lbuffer/rbuffer content into the request JSON |
| T-3.2-03 | Denial of Service | Orphaned FIFO on widget crash or Zellij failure | mitigate | EXIT ERR INT trap calls _qq_cleanup (rm -f) before resetting itself; IFS= read -r -t 30 timeout prevents indefinite blocking if pane never writes; || true after read ensures widget continues even on timeout (treats as cancel) |
| T-3.2-04 | Tampering | zellij run path injection via QQ_DEV_ROOT or PATH manipulation | accept | qq is resolved via PATH which is user-controlled by design in the shell environment; QQ_DEV_ROOT is only used by _qq_prewarm_daemon (unchanged); the qq client path is not constructed from env vars in the Zellij run command |
</threat_model>
