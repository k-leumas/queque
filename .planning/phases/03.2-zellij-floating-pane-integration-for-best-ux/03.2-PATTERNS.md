```typescript
export async function writeShellResult(resultFile: string, result: ShellResult): Promise<void> {
  // Validate the result shape — catch programming errors early
  const parsed = shellResultSchema.parse(result);

  const line = `${JSON.stringify(parsed)}\n`;

  // Detect named pipe: rename(2) would replace the FIFO inode and break
  // the waiting zsh reader. Direct writeFile delivers data to the open reader.
  let isFifo = false;
  try {
    const st = await fsp.stat(resultFile);
    isFifo = st.isFIFO();
  } catch {
    // Path does not exist yet (regular file not created) — not a FIFO
  }

  if (isFifo) {
    // Named pipe: direct write — no atomic rename
    await fsp.writeFile(resultFile, line, { encoding: 'utf-8' });
  } else {
    // Regular file: atomic rename for zero-partial-write guarantee
    const tmpFile = `${resultFile}.tmp`;
    await fsp.writeFile(tmpFile, line, { encoding: 'utf-8' });
    await fsp.rename(tmpFile, resultFile);
  }
}
```

**Key changes from current:**
- `stat` call added before write to detect FIFO vs regular file
- FIFO branch: `fsp.writeFile(resultFile, ...)` directly — no tmp file, no rename
- Regular file branch: original atomic-rename pattern preserved verbatim
- Function signature and JSDoc comment updated to describe dual behavior

**Critical non-obvious findings (from RESEARCH.md, verified by experiment):**
1. `fsp.rename(tmp, fifoPath)` replaces the FIFO inode — widget reader gets nothing. Use `fsp.stat().isFIFO()` to branch.
2. `ZELLIJ=0` is set in live sessions — use `[[ -n "$ZELLIJ" ]]` not `[[ "$ZELLIJ" == "1" ]]`.
3. `IFS= read -r -t 30` not `cat` — `cat` blocks forever if Zellij fails to launch.
4. Trap must call `trap - EXIT ERR INT` after cleanup — ZLE widgets run in the user's interactive shell, not a subshell.
5. `MODAL_CHROME_LINES` constant and scroll hack (`\n.repeat()` + `\x1b[NA`) are removed entirely in the Zellij path.
