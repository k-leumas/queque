# Phase 3.2: Zellij floating pane integration for best UX - Context

**Gathered:** 2026-05-13
**Status:** Ready for planning

<domain>
## Phase Boundary

Replace the current inline TTY rendering approach (MODAL_CHROME_LINES blank-line scroll hack + `/dev/tty` gymnastics) with Zellij floating panes. The QueQue modal opens as a proper floating pane in a Zellij session, giving it a clean dedicated viewport and plugin-like lifecycle. Non-Zellij environments receive a clear error message and exit — no dual-path complexity.

Architecture intent: Zellij-plugin-like. The floating pane IS the entire application viewport. No inline rendering inside the current terminal pane. Clean lifecycle: open → interact → select → write result to FIFO → exit → pane closes.

</domain>

<decisions>
## Implementation Decisions

### Zellij Requirement

- **D-01:** Zellij is a **hard requirement**. If `$ZELLIJ` env var is not set, QueQue prints a clear message (e.g. `"QueQue requires Zellij — see [docs]"`) and exits without showing a modal. Non-Zellij support is deferred to Phase 6.
- **D-02:** The existing inline TTY rendering path (Phase 3.1 MODAL_CHROME_LINES approach) is **removed**. There is no fallback rendering mode in this phase.

### Result IPC — FIFO as Result Channel

- **D-03:** The ZSH widget creates a named pipe (`mkfifo`) before launching the floating pane. The FIFO path is passed to the client as the `--result-file` argument.
- **D-04:** The client writes the JSON result (same shape as current shell result: `{"kind":"cancel"}` or `{"kind":"replace-buffer","lbuffer":"...","rbuffer":"..."}`) directly to the FIFO path using the existing `result-writer.ts` logic. No separate temp result file.
- **D-05:** The ZSH widget backgrounds the `zellij run` call, then blocks reading from the FIFO (`read` or `cat`). It unblocks the instant the client writes the result. Widget applies the result to buffers, then cleans up the FIFO.

### Floating Pane Launch

- **D-06:** The ZSH widget launches the floating pane with:
  ```
  zellij run --floating --close-on-exit --width 80 --height 24 -- \
    qq client --request-file "$req_file" --result-file "$fifo_path"
  ```
  Backgrounded (`&!` or `&`) so the widget can immediately block on the FIFO read.
- **D-07:** The request is still passed via a temp JSON file (`--request-file`). Only the result moves to the FIFO channel.

### Client Rendering in the Pane

- **D-08:** `run-foreground.ts` detects `process.env.ZELLIJ` at runtime. When set: skip `/dev/tty` open, skip the blank-line scroll hack, render Ink to `process.stdout` directly. The floating pane IS the viewport — no scroll-room tricks needed.
- **D-09:** Ink `render()` in Zellij context uses no explicit `stdin`/`stdout` options (defaults to `process.stdin`/`process.stdout`). The pane's own TTY is the rendering surface.

### Pane Dimensions

- **D-10:** Fixed pane size: **80 columns × 24 rows**. Width matches the Phase 3.1 modal width (80 col). Height gives enough room for the monocle-style candidate list, search zone, and controls zone.

### Claude's Discretion

- FIFO timeout/cleanup strategy in the ZSH widget (e.g. `read -t 30` timeout, cleanup on ERR/EXIT trap)
- Exact error message copy for the non-Zellij exit path
- Whether to check `$ZELLIJ_SESSION_NAME` vs `$ZELLIJ` for detection (use whichever is more reliable)
- Daemon `ensureDaemon` call — keep or remove for Zellij pane path (Claude assesses if it adds meaningful latency in pane context)
- TTY stream creation block in `run-foreground.ts` — clean removal vs guard

</decisions>

<specifics>
## Specific Ideas

- Architecture model: Zellij plugin UX (like monocle — `https://github.com/imsnif/monocle`). The pane is a dedicated floating window, not an overlay on the current terminal output.
- Pane launch flags: `--floating --close-on-exit --width 80 --height 24`
- FIFO synchronization: widget creates FIFO with `mkfifo`, backgrounds `zellij run`, blocks with `read < "$fifo"` (or `result=$(cat "$fifo")`). Client writes JSON to the FIFO path via `result-writer.ts`.
- Zellij detection: `process.env.ZELLIJ` in Node.js; `[[ -n "$ZELLIJ" ]]` in zsh widget.

</specifics>
