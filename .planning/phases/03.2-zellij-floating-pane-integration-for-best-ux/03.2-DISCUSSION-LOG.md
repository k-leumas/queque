## Zellij Requirement Scope

| Option | Description | Selected |
|--------|-------------|----------|
| Detect + fallback | Check $ZELLIJ, fall back to inline TTY modal if not in Zellij | (initially selected, then revised) |
| Zellij-only | Hard require; exit with message if $ZELLIJ not set | ✓ |
| Zellij-only with graceful message | Same but with install instructions | |

**User's choice:** Zellij-only (revised from initial "Detect + fallback")

**Notes:** User questioned whether a degraded non-Zellij experience makes sense ("does providing crappy support for non-zellij make sense or is that a broken product"). The fallback path means maintaining two rendering modes — old scroll-hack path AND new Zellij pane path. Since the phase goal is explicitly Zellij floating panes, dual-path complexity is not worth it. Non-Zellij support deferred to Phase 6.

## Architecture Frame

| Option | Description | Selected |
|--------|-------------|----------|
| Ink pane in Zellij | Just put the existing Ink TUI in a Zellij floating pane | |
| Zellij-plugin architecture | Pane IS the entire app; plugin-like lifecycle; no inline rendering | ✓ |

**User's choice:** Zellij-plugin-like architecture

**Notes:** User specified "the architecture should follow that of a zellij plugin, very much like monocle." This reframes the approach: the pane is a dedicated viewport, not an overlay. Clean lifecycle: open → interact → select → write result → exit. Reference: https://github.com/imsnif/monocle.

## Result IPC — FIFO vs Other

| Option | Description | Selected |
|--------|-------------|----------|
| FIFO as result channel | Widget creates FIFO, blocks reading it; client writes JSON result directly to FIFO | ✓ |
| Temp file + poll loop | Widget polls result file every ~50ms with timeout | |
| zellij run blocking | Rely on `zellij run` being synchronous, then read temp file | |

**User's choice:** FIFO as result channel directly

**Notes:** Cleanest blocking primitive. No polling, no latency. FIFO path is passed as `--result-file` to the client; `result-writer.ts` writes to it. Widget unblocks instantly when client writes.
