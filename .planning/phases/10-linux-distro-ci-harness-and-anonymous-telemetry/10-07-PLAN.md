<objective>
When the distro smoke fails on a push, open (or update) a pull request that puts the branch back to its last green tree, with the failing distros, `qq doctor --json` and the PTY log tails in the body (D-15). This replaces the roadmap's local pre-push smoke (D-13): failures surface remotely as a ready-to-merge revert.

Purpose: a broken environment never sits silently on a branch; the fix-or-revert decision is one click, and the body has the diagnostics.
Output: `scripts/ci/auto-revert.sh`, `tests/auto-revert.test.ts`, and the `auto-revert` job in `.github/workflows/ci.yml`.

Design choices (Claude's discretion, recorded): offending range = last green → HEAD by the lookup order in must_haves; dedupe by a fixed head branch per source branch plus edit-if-open. The real end-to-end drill (a deliberately broken push on a scratch branch) runs in plan 12 after a human enables "Allow GitHub Actions to create and approve pull requests" (D-21). A stub `gh` in the script's unit test is a test double for an external API, not a smoke stub (RESEARCH Validation Architecture note).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pushed branch name / SHAs → shell | Attacker-influenced strings (any collaborator's branch) reach a job holding a write token |
| CI artifacts → public PR body | Logs and doctor JSON from the smoke container are published |
| workflow token → repository | The job can push branches and open PRs |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-23 | Tampering | branch name in auto-revert.sh | high | mitigate | Passed via `env:` only, `git check-ref-format`, every expansion quoted, no eval; test with a shell-syntax branch name (Task 1) |
