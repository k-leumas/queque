<objective>
Give the daemon its telemetry half: the in-memory buffer and raw `/batch` sender (D-07), the IPC kinds the client and `qq telemetry` use (`telemetry-event`, `telemetry-show`, `telemetry-reset`), the bounded shutdown flush, and error kinds on `fetch-error` so the client can report errors as an enum without ever reading message text.

Purpose: the daemon is the long-lived process that owns the buffer (CONTEXT code_context); everything that leaves the machine passes the strict batch schema here, and `qq telemetry show` can print exactly that (D-12).
Output: `src/daemon/telemetry-buffer.ts`, `src/providers/error-kind.ts`, IPC additions in `src/contracts/ipc.ts`, server and daemon-command wiring, error-kind tagging in claude-default and fetch-client, and three test files.

Design choices (Claude's discretion, recorded): flush every 60 s or at 20 events, cap 100, 3 s send timeout, 1 s shutdown wait. Nothing is buffered without a key, so a keyless build never holds events in memory.

Size rationale (plan-check revision): 3 auto tasks (a raw `<task` count also matches the `<tasks>` wrapper), each touching at most 5 files.
