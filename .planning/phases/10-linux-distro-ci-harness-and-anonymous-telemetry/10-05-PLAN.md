<objective>
Wire the proven scripts into GitHub Actions: a `ci.yml` that runs on every push and PR, skips heavy jobs for doc-only changes without leaving required checks Pending, runs the host checks plus the six-distro vitest and smoke matrices, and gates everything behind one `ci-ok` job. The smoke also asserts `qq doctor --json` exits 0 and keeps its JSON for revert PR bodies.

Purpose: environment breakage on any supported distro is caught on push, before it reaches main (phase goal, D-14), and the gate job makes branch protection simple and safe.
Output: `scripts/ci/code-changed.mjs` (+ test), the doctor step in `scripts/smoke-distro-runner.sh`, `.github/workflows/ci.yml`, `.github/workflows/distro.yml`.

Design choices (Claude's discretion, recorded): PR image pins are ubuntu:22.04, ubuntu:24.04, debian:13, fedora:44, archlinux:latest (rolling; a date pin does not pin packages) and alpine:3.24; the nightly `:latest` set is plan 08. The vitest leg runs through `scripts/ci/test-in-distro.sh` (docker run) instead of a `container:` job: the same script runs locally (D-16 parity), there is no Alpine JavaScript-action or `safe.directory` special case, and CI cannot skip because the script fails when `CI` is set and Docker is missing.

Size rationale (plan-check revision): 3 auto tasks (a raw `<task` count also matches the `<tasks>` wrapper), estimate 75k against the 100k smart-zone budget. Task 1 is one small pure script plus its test, Task 2 is a one-file edit to the runner, and Task 3 is YAML that only orchestrates scripts already proven in plan 01 (no new logic). Not split: `ci.yml` calls the Task 1 script and the Task 2 doctor step, so moving the YAML into its own plan would put it one wave later and push plans 07 and 08 (and everything after them) back a wave too, with no reduction in the files each half reads.
</objective>
