### Code Review Issues (from 03.1-REVIEW.md — not blocking verification)

The code review identified issues that exist in the current code but were not blocking plan-defined must-haves. They are surfaced here for awareness:

**CR-01 (CRITICAL per review):** `onSelect`/`onCancel` in `CandidateSelect.tsx` are typed as `() => void` but callers in `run-foreground.ts` pass `async` functions. The returned Promise is not awaited — if `writeShellResult` fails, `unmount()` is never called and the shell hangs. This is a live defect but not a must-have failure for this phase (the tests pass because the mock resolves immediately).

**CR-02 (CRITICAL per review):** Enter on an empty filtered list passes `undefined` to `onSelect`, which would write `lbuffer: undefined` to the shell buffer. The "no matches" UI copy is rendered but the keyboard handler has no guard.

**WR-01 (WARNING):** Down-arrow on an empty visible list computes `(i + 1) % 0 === NaN`, corrupting `selectedIndex` state.

**WR-02 (WARNING):** `selectedIndex` is not clamped when query narrows the visible list; stale index causes silent undefined on Enter.

These are not captured in the phase must-haves but represent real behaviour gaps that will surface during human verification (items 2 and 5 in the Human Verification section above).
