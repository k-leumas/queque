# Phase 03.1 — UI Design Contract: Monocle-style Interface and Interactivity

> Visual and interaction contract for terminal UI phases. Generated by gsd-ui-researcher.
> This is a terminal UI (TUI) project using Ink (React for terminals). There is no CSS,
> no browser, no Tailwind, no shadcn. All "design" is expressed through ANSI colors,
> Ink Box/Text props, and keyboard event handlers.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | Ink 7.0.1 (React for terminals) |
| Preset | not applicable — terminal context |
| Component library | Ink primitives: `Box`, `Text`, `useInput` |
| Icon library | Unicode box-drawing characters + glyphs (no icon package) |
| Font | Terminal monospace (host-defined — no font control) |

Source: `package.json`, existing `src/ui/Modal.tsx` and `src/ui/CandidateSelect.tsx`

## Spacing Scale

Terminal spacing is measured in character cells (columns) and rows, not pixels.
All padding and margin values are expressed as character-unit integers.

| Token | Value | Ink Prop | Usage |
|-------|-------|----------|-------|
| tight | 0 | `paddingX={0}` / `marginTop={0}` | Between glyphs and text on the same row |
| xs | 1 col / 0 row | `paddingX={1}` | Modal inner horizontal padding (existing, keep) |
| sm | 2 cols | `marginLeft={2}` | Indent for inactive candidate rows |
| md | 1 row | `marginTop={1}` | Between modal sections (header, body, footer) |
| lg | 2 rows | `marginTop={2}` | Between distinct UI zones (search → results) |
| control-reserved | 3 rows | layout constant | Bottom rows reserved for controls line (matches monocle model) |

Exceptions: Touch targets do not apply to terminal UI. No 44px minimums.

## Typography

Terminal "typography" = ANSI text attributes applied via Ink `Text` props.
Font size is always 1 cell tall — the terminal controls it. Weights map to bold/dim.

| Role | Ink Props | Usage |
|------|-----------|-------|
| Active command | `bold color="white"` | Selected candidate command text |
| Active label | `bold color="green"` | Selection glyph on active row (monocle uses green for selection) |
| Inactive command | `dimColor` | Unselected candidate command text |
| Explanation / meta | `dimColor` (no bold) | Inline explanation after `—` separator |
| Search label | `bold color="cyan"` | "SEARCH:" prefix in the search input area |
| Search term | default (no style) | User-typed query text |
| Header title | `bold color="cyan"` | Modal title ("queque") |
| Section rule | `dimColor` | Horizontal separator line `─────` |
| Controls key | `bold` + bg `gray` (238) + fg `white` (15) | Key badge in controls line |
| Controls text | default bg `gray` (245) + fg `black` (16) | Control description text |
| Loading state | `dimColor italic` (if supported) | "Scanning…" / spinner text while waiting |

Line height is always 1 (terminal is fixed-grid). No line-height ratio applies.

## Color

Terminal colors expressed as named ANSI colors (Ink named values) or ANSI 256-color
indices where named values are insufficient. All values are foreground unless noted.

Reference palette derived from monocle source (`src/ui/mod.rs`):

| Role | Value | Usage |
|------|-------|-------|
| Dominant surface | terminal default bg | Background of the entire modal interior |
| Border | `cyan` (named) | Modal border (`borderColor="cyan"`) — existing, keep |
| Active selection fg | `green` (named) / ANSI 154 | Selected row command text and glyph |
| Active selection glyph | `"┌>"` in `orange` / ANSI 166 | Selection arrow replacing existing `❯` |
| Match highlight | ANSI 238 bg + `bold underline` | Matched characters within results (fuzzy filter phase) |
| Dim / inactive | `dimColor` (Ink prop) | Unselected rows, separators, explanations |
| Search label | `cyan` (named) | "SEARCH:" label text |
| Controls key bg | ANSI 238 (gray light) | Key badge background |
| Controls key fg | `white` / ANSI 15 | Key badge text |
| Controls text bg | ANSI 245 (gray dark) | Control description background |
| Controls text fg | `black` / ANSI 16 | Control description text |
| Active control dot | `red` / ANSI 124 | Active indicator dot in mode-toggle controls |
| Inactive control dot | `dimColor` | Inactive indicator dots |
| Loading / scanning | `dimColor` | Spinner / status text |

Accent reserved for:
- The active selection glyph (`┌>`) only
- The "SEARCH:" label prefix
- The modal border

The `cyan` border is the dominant accent. `green` is used exclusively for the selected
result row. `orange` is used exclusively for the selection glyph. No other elements
receive accent treatment.

Destructive color (`red`): reserved for the active-mode dot indicator in the controls
line. There are no destructive actions in this phase (no delete, no clear).

## Layout Structure

The modal renders three vertical zones, matching the monocle three-zone model:

```
╭──────────────────────────────────────────────────────────╮
│  queque                                                  │  ← Header zone (2 rows: title + rule)
│ ─────────────────────────────────────────────────────── │
│  SEARCH: {query text}                                    │  ← Search zone (1 row)
│                                                          │
│  ┌> git status --short           — show working tree    │  ← Results zone (dynamic rows)
│  │  git diff --stat              — summarise changes    │    active: green fg + ┌> glyph
│     git log --oneline -5         — recent commits       │    inactive: dim + 2-space indent
│                                                          │
│  ↑↓ select · enter accept · esc cancel  Ctrl+f filter   │  ← Controls zone (1 row, full width)
╰──────────────────────────────────────────────────────────╯
```

Layout rules:
- Modal width: **80 cols** (upgraded from existing 62 — monocle uses full terminal width;
  80 is a safe maximum for split-terminal scenarios)
- Inner width: `modal_width - 4` (2 border + 2 paddingX)
- Header: always 2 rows (title + horizontal rule)
- Search zone: always 1 row
- Gap between search and results: 1 row (`marginTop={1}`)
- Results zone: fills available height; max **5 candidates** (existing contract, keep)
- Gap between results and controls: 1 row (`marginTop={1}`)
- Controls zone: always 1 row (the footer line)
- Total minimum height: 8 rows (2 header + 1 search + 1 gap + 1 result + 1 gap + 1 controls)

## Selection Glyph Contract

Monocle uses `┌>` (box-drawing + arrow) instead of a plain `❯`. QueQue adopts this:

| State | Glyph | Color | Indent |
|-------|-------|-------|--------|
| Active row (first line) | `┌>` | `orange` / ANSI 166 | 0 |
| Active row (continuation) | `│ ` | `dimColor` | 0 |
| Below-active row | `│ ` | `dimColor` | 0 (2-space indent equivalent via glyph) |
| Unselected row | `  ` (2 spaces) | — | 0 |

The existing `❯` glyph is replaced by `┌>` to match the monocle selection model.

## Interaction Contract

### Keyboard Map

| Key | Action | Current State |
|-----|--------|---------------|
| `↑` | Move selection up (wraps) | Implemented in `CandidateSelect.tsx` |
| `↓` | Move selection down (wraps) | Implemented in `CandidateSelect.tsx` |
| `Enter` | Accept selected command → write to shell buffer | Implemented |
| `Esc` | Cancel → restore original shell buffer | Implemented |
| `Backspace` | Delete last char from live search query | NEW (Phase 03.1) |
| Any printable char | Append to live search query, filter candidates | NEW (Phase 03.1) |
| `Ctrl+F` | Toggle floating/tiled mode (monocle model — future; log as deferred) | DEFERRED |
| `Ctrl+R` | Toggle filter type (monocle model — future; log as deferred) | DEFERRED |

### Live Search / Fuzzy Filter

- A search input row ("SEARCH: {query}") is always visible at the top of the results zone.
- The initial query text is pre-populated from the shell pre-buffer (text typed before `??`).
- As the user types, candidates are filtered in real-time (client-side filter over the
  returned candidate list — no re-query to provider in this phase).
- Filter is case-insensitive prefix/substring match (not full fuzzy in this phase;
  fuzzy is Phase 4 scope per REQUIREMENTS TUI-01).
- Matched characters within the command text are highlighted: bold + underline on the
  matching substring.
- If the filter produces zero matches, show the empty state copy (see Copywriting).

### Navigation Wrap Behavior

- Arrow up from index 0 → moves to last result (wraps).
- Arrow down from last index → moves to index 0 (wraps).
- Existing behavior in `CandidateSelect.tsx` — keep unchanged.

### Focus Model

- The TUI opens with keyboard focus captured by `useInput` immediately.
- All keystrokes go to the Ink component; no focus management between sub-components
  is needed in this phase (single interactive surface).
- `Esc` always cancels regardless of filter state.

## Copywriting Contract

All copy is rendered as terminal text. Character count matters — stay within modal
inner width (76 chars at 80-col modal).

| Element | Copy | Max length |
|---------|------|-----------|
| Modal title | `queque` | 6 chars |
| Search label | `SEARCH:` | 7 chars + space |
| Search placeholder (empty query) | `type to filter…` | 16 chars |
| Controls footer | `↑↓ select · enter accept · esc cancel` | 38 chars |
| Empty filter state | `no matches — try a different query` | 35 chars |
| Error state (provider failure) | `provider error — press esc to return` | 37 chars |
| Loading / thinking | `thinking…` | 10 chars |
| Waiting for daemon | `connecting…` | 12 chars |

No destructive actions exist in this phase. No confirmation copy needed.

Primary CTA: `enter` key (no label button — terminal-native, key-driven).
The footer hint line IS the primary CTA affordance.

## Animation / Loading State

Monocle shows an animated loading state while results are being fetched. QueQue must
do the same since provider calls are async.

- A single spinner row replaces the results zone while loading.
- Spinner cycles through: `thinking…`, `thinking.`, `thinking..`, `thinking…`
  (or an equivalent dot-cycle) at 200ms intervals.
- Use Ink's `useState` + `useEffect` interval; no third-party spinner package.
- Spinner text: `dimColor`, left-aligned, matching the candidate row indent.
- On result arrival, spinner is replaced by the candidate list instantly (no fade).

## Npm Package Safety

This phase introduces no new npm packages. All rendering uses:
- `ink` 7.0.1 (existing, locked)
- `react` 19.2.0 (existing, locked)
- Native Node `setTimeout`/`setInterval` via `useEffect`

No registry vetting gate required. No third-party Ink ecosystem packages added.

If a future sub-plan wishes to add `ink-spinner` or similar, a safety review must
confirm the package does not make network calls or access environment variables.
