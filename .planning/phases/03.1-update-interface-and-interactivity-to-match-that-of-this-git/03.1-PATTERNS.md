**Analog:** `src/ui/CandidateSelect.tsx` lines 27–29 — closest `useEffect` pattern in the codebase (although the spinner's useEffect is for animation, not initialization)


**Core pattern** — `useState` + `useEffect` interval (Research Pattern 4):
```tsx
const FRAMES = ['thinking…', 'thinking.', 'thinking..', 'thinking…'];

export function LoadingSpinner(): ReactElement {
  const [frame, setFrame] = useState(0);

  useEffect(() => {
    const id = setInterval(() => {
      setFrame(f => (f + 1) % FRAMES.length);
    }, 200);
    return () => clearInterval(id);   // CRITICAL: cleanup prevents timer leak (Research §Anti-Patterns)
  }, []);   // empty deps: runs once on mount, cleans up on unmount

  return (
    <Text dimColor>{FRAMES[frame]}</Text>
  );
}
```

**Error handling** — none; `clearInterval` in cleanup handles the only failure mode (timer leak on unmount)

## Key Implementation Constraints

### `renderModal` Refactor — Exposing `rerender`
The current `renderModal` at `src/client/run-foreground.ts` lines 209–243 uses a local `unmount` closure inside the `Promise`. To expose `rerender` to the `llm` branch, one of two approaches is valid:

**Approach A (recommended — simpler):** Inline the modal launch directly in the `llm` branch instead of calling `renderModal`, capturing `app.rerender` from the `render()` return value.

**Approach B:** Change `renderModal` to accept an `onRerender` callback parameter and call it immediately after `app = render(...)`.

Both avoid ref leakage. RESEARCH.md recommends Approach A.

### `MODAL_CHROME_LINES` Count
Current value: `7` (line 217 of `run-foreground.ts`). New value: `9`. Calculation from RESEARCH.md §Pitfall 1:
```
border-top + title + separator + search + gap(search→results)
+ gap(results→controls) + controls + border-bottom = 8
+ body marginTop(1) = 9
```

### JSX in `.ts` files
`tsconfig.json` sets `"jsx": "react"` — React must be in scope for JSX. All `src/ui/*.tsx` files already have `import React from 'react'` or `import React, { ... } from 'react'`. New component files must include this import.

### Test File Extension
`vitest.config.ts` `include` pattern is `tests/**/*.test.ts`. A new `tests/candidate-select.test.tsx` will NOT be picked up without a config change. Planner should decide: rename to `.test.ts` (JSX works via tsconfig) or add `**/*.test.tsx` to the include array.
