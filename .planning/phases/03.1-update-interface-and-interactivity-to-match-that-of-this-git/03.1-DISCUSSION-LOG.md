## Initial Search Filter

| Option | Description | Selected |
|--------|-------------|----------|
| Show all candidates | All LLM-returned candidates are visible on load; lbuffer text is visual context only | |
| Pre-filter on load | Candidates are filtered by lbuffer text when modal first renders | |
| Both (conditional) | Empty lbuffer → show all; non-empty lbuffer → pre-filter | ✓ |

**User's choice:** Both — if lbuffer is non-empty, pre-filter candidates on first render; if lbuffer is empty, show all candidates.
**Notes:** The user explicitly specified conditional behavior rather than choosing one of the presented options.

## Single-Candidate Behavior

| Option | Description | Selected |
|--------|-------------|----------|
| Always show the modal | Modal always appears; user can cancel even for single result | ✓ |
| Fast-accept (keep current) | 1 result = immediate shell buffer write, no modal | |

**User's choice:** Always show modal, with best candidate preselected at top (index 0) and other candidates below.
**Notes:** User clarified they want all returned candidates visible, with the best one preselected. Sort order is provider-owned (first candidate = best) — `CandidateSelect` renders as received.

Follow-up — Sort order:
| Option | Description | Selected |
|--------|-------------|----------|
| Provider owns sort order | LLM returns candidates ranked best-first; UI renders as-is | ✓ |
| CandidateSelect re-sorts | UI has its own ranking logic | |
