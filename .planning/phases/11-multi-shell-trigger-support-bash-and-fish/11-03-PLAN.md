<objective>
Make the client half of installed-tool awareness shell-aware, so a bash user's "not installed" flags and prompt steering are as correct as zsh's: a `tools.pending` marker protocol lets a slow shell-side scan run alongside client startup (D-05), and the command-word lexer reads bash syntax for bash (D-02).

Purpose: bash's compgen scan costs ~85 ms (spike 005) and D-05 requires it to overlap Node startup, not precede it. The client today reads the handoff eagerly and treats a missing file as "no flags", so a backgrounded writer would race. The marker removes the race for every shell (fish reuses it in Phase 12).
Output: `TOOL_HANDOFF_PENDING`, `TOOL_HANDOFF_PENDING_BUDGET_MS = 500` (open question 2: a named constant, not configuration), `TOOL_HANDOFF_PENDING_POLL_MS = 10`, `readToolHandoff(dir, { shell, pendingBudgetMs })`, start-early/await-late in run-foreground, per-shell lexer tables, `ToolInventory.shell`, tests. Plan 07 writes the bash side (marker, detached writer, two-flag cleanup).

Expected duration: 30-45 min. Runs in parallel with plans 02, 04 and 06.
</objective>
